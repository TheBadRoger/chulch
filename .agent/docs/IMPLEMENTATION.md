# chulch 实现任务书

使用 Rust 实现 Windows CLI，真实启动验收覆盖 Fabric、Forge、NeoForge。导入支持 Modrinth `.mrpack` 和 CurseForge 导出 ZIP。采用自定义存储布局，由加载器适配器生成必要的兼容路径。先交付本地离线原型，再接入微软正版登录。

## 工程起点

- 单 Cargo package，二进制入口处理参数和输出，库模块实现导入、下载、存储、加载器、视图和 Java 进程。持久化采用有版本字段的 JSON 与独立对象文件。预留结构化玩家身份输入，以便后续接入登录。
- 第一个改动交付 CLI、版本化本地测试清单、SHA-256 对象入库及 Fabric 的启动直通路径。测试清单指向本地合法工件。以两个独立实例进入单人世界、存盘、重启及对象去重验证结束第一阶段。

## 导入、下载与适配器

- 导入器输出统一安装计划，包含精确版本、客户端文件条目、源哈希、来源标识、目标路径与覆盖顺序。Modrinth 应处理客户端环境筛选及两层客户端 overrides。CurseForge 应保留项目与文件 ID、可选条目及 overrides 路径。受限文件显式进入待补齐状态。
- 下载路由按资源类型选择端点，首版实现上游、BMCLAPI 的可用路由和用户配置镜像。元数据、客户端、资源、Maven 和模组分开注册能力。失败按候选顺序回退，记录命中及错误。固定预期身份和校验值，切换传输源不得换版本或降低校验等级。凭证不进入镜像请求。没有可信源哈希的条目记录完整性状态。
- 每种加载器独立实现 `resolve`、`prepare`、`launchPlan`。安装器和处理器只在暂存工作区写入，读取成品后再提交对象库。启动计划包含 Java 可执行文件、工作目录、参数数组、环境、游戏目录、库与资源路径、native 目录及模组视图。兼容路径只由适配器约束，核心不依赖传统启动器目录结构。
- Java 运行阶段共享客户端和库等输入，可单独传路径就直接引用。对目录扫描输入，验证可改扫描根则按需提供专用视图，要求相对路径则在实例游戏目录创建托管条目。只对已实测且声明不可变的工件创建同卷硬链接。跨卷或未知行为用私有副本。用户修改、配置、存档、日志和运行缓存永远独立。清理运行视图时只删除受清单管理的路径，避免通过链接修改源对象属性或字节。

## 数据契约

- Blob：`sha256`、`size`；物理路径 `store/blobs/sha256/<prefix>/<hash>`。对象身份由实际字节决定；来源 URL 及源声明哈希作为独立字段保留。凭证单独管理，禁止写入锁文件与日志。
- Layer：`schemaVersion`、`kind`、有序解析所需的依赖、映射条目。条目至少有 `target`、`blob`、`role`，角色区分共享工件与私有初始化模板。定义规范化序列化后对清单寻址。
- Generation：记录有序层 ID、解析后的托管路径、具体 Minecraft/加载器版本及平台、Java 约束、主类和参数来源。实例同时维护当前 generation 引用与私有数据目录。未识别的 schema 版本要报错，保留现有记录。
- 解析以规范化目标路径检测同名冲突。Windows 下同时拒绝大小写冲突、设备名、备用数据流以及重解析点导致的根目录逃逸。导入只读源实例，ZIP 路径校验与大小限制在解包前或流式读取时生效。

## 写入与生命周期

1. **入库**：流式写同卷临时文件，校验长度及源格式提供的哈希，再按内部 SHA-256 发布。并发命中同一哈希时验证并复用。发现损坏时报告受影响实例，走修复流程。
2. **准备**：编译层映射与启动计划，检查所有引用可读，构建候选运行视图。可写模板以独立文件初始化，保留用户现有文件，明确拒绝托管文件与用户文件的冲突。
3. **提交**：在实例锁内发布 generation，原子切换当前指针；上一代可用至更新成功。私有数据独立于版本切换。启动、重启恢复和清理识别未提交暂存目录。
4. **运行**：按参数数组创建 Java 进程。处理平台规则、classpath 顺序、native 解压及资源路径。每个实例独占运行锁，运行期间固定 generation，更新或删除需等该实例退出。对日志中的认证参数做脱敏。
5. **回收**：在同一个跨进程存储协调边界内计算引用与删除对象。标记根包括当前代、保留的历史代、进行中的事务和活动运行引用。先预览再执行，清理失败允许重试。删除实例的私有数据需单独获得用户确认。

## 开发顺序与验收

| 阶段 | 实现 | 验收 |
| --- | --- | --- |
| 1 | 本地离线 Fabric 启动、Blob 和锁定清单 | 两实例均可启动并独立存盘，同内容对象只入库一份 |
| 2 | 两种分发格式、官方下载和镜像路由、补齐及 Forge/NeoForge 适配 | 三种加载器进入游戏，两种包格式完成安装，镜像失败可回退 |
| 3 | 共享写入验证、更新、回退、对象核验与清理预览及执行 | 中断后可重试，旧代可启动，清理保护有效对象，记录实际磁盘占用 |
| 4 | 应用注册、微软正版登录、凭证刷新和退出 | 以正版账号启动，验收权益检查、过期及撤销，凭证从日志和清单中排除 |

验证异常路径包括下载截断、同哈希并发入库、路径碰撞、磁盘空间不足、损坏对象及 JVM 异常退出。测量独立安装、导入后、同时运行和退出后的磁盘占用。硬链接按文件身份计一次，复制按实际副本计数。回退目标为包托管文件与启动参数，存档与配置快照作为独立能力设计。

首版验收矩阵必须覆盖两种发行格式、三种加载器、官方源、BMCLAPI 实际命中、自定义镜像、校验失败回退及有缺件的导入。在三种加载器各自的真实测试包上记录安装与 JVM 进程树的文件行为。用私有副本先跑首次启动、设置保存、世界存盘、正常退出和相关更新路径，再核对写入事件及对象哈希，最后复测共享视图。记录 Minecraft、加载器、Java 和包版本，未经验证的组合不得宣称可安全硬链接。

运行视图通过单独的物化接口接入平台实现。将来验证写时复制时应测试覆盖、删除、改名与回收。进程级隔离单独验证可见文件、进程与网络边界。
