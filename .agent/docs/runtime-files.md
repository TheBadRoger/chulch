# 运行时文件与磁盘验证

下面是首版设计分类。文件被读取或由 JVM 加载并不代表它只在启动瞬间用到。对象可能在整个进程生命周期被打开、映射或再次读取，运行期间需保留引用。分类目前基于启动机制和加载器文档，具体版本与模组组合仍须动态验证。

| 文件 | 安装或运行时行为 | 落位 |
| --- | --- | --- |
| 客户端 JAR、普通 Java 库、加载器 JAR | 安装产生或下载，运行阶段作为 classpath 或模块路径输入 | 按内容共享，通过启动参数提供对象或兼容路径 |
| Forge、NeoForge 安装处理器输入和派生产物 | 安装器可生成或补丁处理文件，运行时读取已经生成的产物 | 在独立工作区执行安装步骤，校验成品后入库。保留适配器所需路径 |
| 资源索引与资源对象 | 下载阶段写入，运行时作为资源输入。旧版可能依赖派生资源树 | 共享已校验对象。按版本生成其要求的资源目录视图 |
| Native 压缩包与解压后的 DLL | 压缩包是下载输入，解压目录是启动器生成的工作数据，DLL 可在运行期间保持打开 | 压缩包共享，解压目录按运行视图管理 |
| 模组和 Fabric API 等 JAR | 加载器通常读取；单个模组可实现自更新、写回或下载额外文件 | 已验证的托管 JAR 可使用共享路径或同卷硬链接。未知或观察到改写的文件用私有副本，持久更新使用实例私有文件 |
| `config/`、`options.txt`、`servers.dat`、`saves/` | 设置保存、服务器列表编辑、世界存盘，以及模组首次启动生成或更新配置 | 实例私有。包提供的默认内容作为初始化模板 |
| `logs/`、`crash-reports/`、`screenshots/`、服务器资源包缓存、模组生成目录 | 按运行行为生成，具体命名随版本或模组变化 | 实例私有或运行私有。未知新目录默认归入实例 |
| 整合包随附的脚本、资源包和光影包 | 按模组与用户工作流可能读取、替换或修改 | 默认私有；只有声明托管且验证只读的条目可共享 |

Fabric 适配器可验证 `fabric.modsFolder`，将模组扫描定位到独立视图。Forge 和 NeoForge 适配器先验证各目标版本对游戏目录、模组目录、库路径和参数文件的要求。在需要相对路径发现时，为该加载器构建最小兼容视图。

## Windows 实测步骤

1. 每种加载器记录 Minecraft、加载器、Java、整合包版本和数据目录。先用私有副本运行，避免分类验证影响共享对象。
2. 用 Sysinternals Process Monitor 记录安装器、JVM 及子进程的文件操作。区分读取、请求写权限、实际写入、创建、截断、重命名与删除。检查游戏目录、对象库、临时目录和用户数据目录。
3. 覆盖首次启动、二次启动、设置保存、创建世界并存盘、退出、模组自更新（若有）和异常退出。对托管候选项比对前后哈希与文件清单。
4. 为每个适配器保存验证矩阵。共享候选若在测试中发生写入、替换，或必须以写权限打开才能运行，则改成私有落位。验证过的硬链接以文件身份计一次空间，并检查运行后对象库哈希保持一致。异常时标记受影响对象与实例，修复后才能恢复共享。

硬链接共享同一个文件对象，目录分开也无法隔离原地改写。普通模组和加载器在当前用户权限内运行，因此只在已验证的组合上启用链接，跨卷时使用直接路径或复制。借鉴 Docker 的写时复制与进程隔离可作为后续独立原型。
